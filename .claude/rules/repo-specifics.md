# Repository Specifics

- Fork of `Aleph-One-Marathon/alephone`. `upstream` remote push is disabled. Never PR, push a branch, or file an issue upstream — upstream's maintainer said in writing they will not take patches from porting projects. This is explicitly *permitted* by them, just never upstreamed.
- **This is a real GitHub fork of an active repo, so bare `gh issue list` / `gh issue view` resolve to `Aleph-One-Marathon/alephone` (580+ unrelated issues), not this fork.** Verified 2026-08-23 — `gh repo view` confirms `isFork: true`. Always pass `-R matthewdeaves/alephone` explicitly. This is the one repo in the fleet where the shared brief's "bare `gh issue list` reads the git remote and cannot get the name wrong" does not hold — the other four ports aren't forks of a live upstream.
- Scenario data (three Marathon games) are submodules under `data/Scenarios/`. This repo ships code, same content rule as the other four ports.
- `tests/` + Catch2 (`replay_film_test.cpp`) is the existing verification oracle for endian/replay correctness — use it, don't build a parallel one.
- `scripts/` exists now (build, package-dmg, deploy-dmg, smoke-dmg, pick-bench-host, pick-build-host, etc.) — largely mirrors `old-mac-quakespasm`'s fleet tooling shape. Raise gaps or divergence with `old-mac-build-host` as `from:port` rather than hand-rolling a fix here.
- **Client release tags are `vX.Y.Z` (semver), e.g. `v1.0.0`** — user request 2026-09-03, replacing the old ad-hoc `release-YYYYMMDD-fat-N` scheme (still present as historical tags, don't rename those). `scripts/package-dmg.sh`'s `VERSION=` already matches `v[0-9]*` via `git describe`, so no script change was needed, just the convention going forward. Server releases keep their own `server-vX.Y.Z` stream, untouched by any of this. Give each release a real name in its GitHub Release title, not the bare tag.
- **Fleet-wide policy (`retro-agents/briefs/GRANTS.md`, commit `7a4d0ef`, user-confirmed): on every new client release, prune older client GitHub Releases (and their tags) so only the latest stays published.** Server-`*` releases are untouched by this. Deleting a release is outward-facing and irreversible — the Claude Code auto-mode permission classifier blocks `gh release delete`/tag-delete outright regardless of this standing grant (hit live 2026-09-03), so pruning needs either the user to run it directly or a Bash permission rule added for it; don't attempt to work around the block.
